2 Deuda Técnica y Riesgos Críticos de Seguridad

CRÍTICO: Sincronización Automática de Base de Datos La opción synchronize: true está habilitada en TypeOrmModule. En cualquier entorno fuera de desarrollo local, esto puede destruir tablas o alterar el esquema irremediablemente.
ALTO: Credenciales y secretos codificados en el código (Hardcoding) Contraseñas de la base de datos ('Toro2024') están expuestas en texto claro en app.module.ts. Esto viola prácticas estándar de DevOps y normativas de seguridad (ISO 27001 / OWASP).
MEDIO: Falta validación global (ValidationPipe) Es indispensable confirmar que se ha implementado la validación de DTOs utilizando class-validator y class-transformer a nivel global, para evitar inyección de datos maliciosos.

3 Estrategia de Actualización de Core (NestJS 9 a 10)

Pasos recomendados para realizar una migración segura sin romper la funcionalidad en producción.

  • Auditoría previa y actualización de Node.js

    Asegurarse de tener instalado Node.js v20.x localmente. Borrar node_modules y package-lock.json.

    Bashnvm use 20
rm -rf node_modules package-lock.json
  • Actualizar el framework (CLI y dependencias Core)

    Utilizar la herramienta de CLI de Nest para forzar la actualización del ecosistema.

    Bashnpm check-updates -u
# O manualmente:
npm i -g @nestjs/cli
nest update -t 10
  • Actualización de TypeScript y ecosistema Reactivo

    NestJS v10 abandonó RxJS v7 interno y cambió la compatibilidad. Asegurar compatibilidad de Types.

    Bashnpm i typescript@5.1.x rxjs@7.8.1 reflect-metadata@0.2.1

4 Modernización y Patrones de Arquitectura

Propuesta de refactorización de configuración (app.module.ts) implementando el patrón ConfigModule asíncrono y variables de entorno.

Refactorización: TypeOrm y Variables de Entorno

Configurar TypeORM de manera segura utilizando ConfigModule y cargando `TypeOrmModule.forRootAsync`.

app.module.ts (Refactorizado)import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { TypeOrmModule } from '@nestjs/typeorm';

@Module({
  imports: [
    // 1. Inicializar gestión de variables de entorno (.env)
    ConfigModule.forRoot({
      isGlobal: true, 
      envFilePath: '.env', // No commitear en GIT
    }),

    // 2. Carga asíncrona de base de datos
    TypeOrmModule.forRootAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (configService: ConfigService) => ({
        type: 'mysql',
        host: configService.get<string>('DB_HOST'),
        port: configService.get<number>('DB_PORT'),
        username: configService.get<string>('DB_USERNAME'),
        password: configService.get<string>('DB_PASSWORD'),
        database: configService.get<string>('DB_NAME'),
        entities: [__dirname + '/**/*.entity{.ts,.js}'],
        
        // CRÍTICO: Nunca sincronizar en prod, usar Migraciones
        synchronize: configService.get<string>('NODE_ENV') === 'development',
        
        // Logs de DB (útil en dev)
        logging: configService.get<string>('NODE_ENV') === 'development',
      }),
    }),
    
    // ... [Resto de tus módulos] ...
  ],
})
export class AppModule {}

Habilitar Validaciones y Transformaciones Globales

Añadir interceptores de seguridad en main.ts para validar los DTOs por defecto y evitar payload polution.

main.ts (Update)import { ValidationPipe } from '@nestjs/common';
// ...

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  
  // Habilitar la validación global de DTOs automatizada
  app.useGlobalPipes(new ValidationPipe({
    whitelist: true, // Borra campos no definidos en el DTO
    forbidNonWhitelisted: true, // Retorna error 400 si hay campos extra
    transform: true, // Transforma primitivos a string, int, boolean implícitamente
  }));

  // CORS de forma segura
  app.enableCors({ origin: '*' /* reemplazar por dominios permitidos */ });

  await app.listen(process.env.PORT || 3000);
}
